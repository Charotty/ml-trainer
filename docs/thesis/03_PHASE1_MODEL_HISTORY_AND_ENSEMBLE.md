# 03. История Phase 1 и устройство оптимизированного ансамбля

## 1. Почему Phase 1 можно считать «ядром» текущей поставки
В текущей рабочей копии репозитория production-путь для предсказания реализован так:

- `models/adaptive_ensemble.pkl` — основной артефакт модели
- `src/api/kidney_displacement_api.py` — сервис, который этот артефакт загружает и использует
- `models/phase1/adaptive_ensemble.py` — код, который определяет:
  - список признаков,
  - создание engineered и cross-features,
  - обучение базовых моделей,
  - оптимизацию весов ансамбля.

Поэтому Phase 1 описывается в диссертации не как «черновой этап», а как **основной инженерный результат**, доведённый до API.

## 2. Основные инженерные проблемы, которые решались

### 2.1. Малые данные и риск переобучения
Ситуация: медицинские проекты часто имеют ограниченное число пациентов/кейсов. Это делает “тяжёлые” модели (особенно глубокие сети) менее эффективными.

Решение в Phase 1:
- перейти к ансамблю относительно устойчивых моделей (RandomForest + линейные модели с регуляризацией);
- оптимизировать веса ансамбля по метрике MAE.

### 2.2. Разнородность источников данных
Ситуация: признаки могут приходить из нескольких источников (DICOM-экстракция + клинические таблицы + внешние наборы).

Решение:
- объединение в `data/processed/*.csv` и использование единого “интегрированного” датасета.

### 2.3. Несогласованность train/inference feature engineering
Ситуация: если в обучении признаки создаются одними формулами, а в API — другими, качество и стабильность падают.

Решение (в рамках текущего API):
- API использует **те же приватные методы** `AdaptiveEnsembleTrainer` (`_create_engineered_features`, `_create_cross_features`) для генерации признаков.

## 3. Архитектура модели AdaptiveEnsembleTrainer
Файл: `models/phase1/adaptive_ensemble.py`

Класс: `AdaptiveEnsembleTrainer`

### 3.1. Основные внутренние компоненты
- `StandardScaler` (`self.scaler`) — масштабирование признаков.
- `SimpleImputer(strategy='median')` (`self.imputer`) — заполнение пропусков медианой (внутри класса объявлено; фактическое применение зависит от участка кода).
- `KFold(n_splits=5, shuffle=True, random_state=42)` (`self.cv_splitter`) — кросс-валидация для оценки моделей.
- Списки колонок:
  - `required_features` — базовые признаки
  - `engineered_features` — производные признаки
  - `cross_features` — кросс-признаки (нелинейные комбинации)
  - `target_columns` — цели (6 дельт)

### 3.2. Базовые признаки (required_features)
Смысловая группа признаков:
- положение центров почек в относительной системе (`*_center_*_rel`)
- размеры почек (длина/объём)
- размеры тела (ширина/глубина/площадь)
- расстояния почек до “опорных” структур (позвоночник, центр тела)
- координаты центра позвоночника и центра масс

Важно для диссертации:
- пояснить **почему именно эти признаки**: они отражают геометрию и “условия” для смещения при изменении положения.

## 4. Feature engineering Phase 1

### 4.1. Engineered features (13)
Создаются в `_create_engineered_features(df)`.

Ключевые идеи:
- **нормализация** (деление на `body_width_mm`) чтобы уменьшить вариативность масштаба пациентов;
- **асимметрии** (лево-право) как сигнал анатомических отличий;
- **признак положения пациента** (`patient_position_encoded`) — если отсутствует, ставится default.

Пример формулы:
- `body_ratio = body_width_mm / body_depth_mm`

### 4.2. Cross-features (15)
Создаются в `_create_cross_features(df)`.

Ключевые идеи:
- “объём тела” как прокси-оценка
- отношения объёма и длины почки (условная плотность)
- расстояние COM–spine
- взаимодействия вида `distance * volume`
- индексы положения (sqrt суммы квадратов координат)
- оценка угла между почками (упрощённо, по XY)

Диссертационный акцент:
- показать, что это **встраивание предметного знания** (medical domain knowledge) в машинное обучение.

## 5. Базовые модели и их роль
Метод `load_base_models()` задаёт 4 модели с параметрами:

- RandomForestRegressor
  - важные параметры: `n_estimators`, `max_depth`, `min_samples_split`, `min_samples_leaf`, `max_features`, `n_jobs`
- Lasso
  - важные параметры: `alpha`, `max_iter`
- Ridge
  - важные параметры: `alpha`, `solver`
- GradientBoostingRegressor
  - важные параметры: `n_estimators`, `learning_rate`, `max_depth`, `subsample`

Диссертационный смысл выбора:
- RF хорошо ловит нелинейности и устойчив на малых данных;
- Lasso/Ridge контролируют переобучение линейной части;
- GB может ловить “тонкие” взаимодействия, но часто требует аккуратной настройки.

## 6. Оптимизация весов ансамбля
Метод: `optimize_ensemble_weights(models, X_train, y_train, X_val, y_val, target_name)`

### 6.1. Идея
Для каждой цели (например, `kidney_left_delta_y`) ансамбль может требовать разных весов базовых моделей.

Алгоритм:
1) обучить каждую базовую модель на `X_train`;
2) получить предсказания каждой модели на `X_val`;
3) решить задачу оптимизации:
   - переменные: веса `w_i`
   - ограничения: `w_i >= 0`, сумма = 1
   - целевая функция: минимизировать `MAE(y_val, sum_i w_i * pred_i)`

Реализация:
- `scipy.optimize.minimize(..., method='L-BFGS-B', bounds=[(0,1),...])`

### 6.2. Почему MAE
- MAE напрямую измеряется в миллиметрах, что удобно клинически.
- MAE менее чувствителен к выбросам, чем MSE.

## 7. Оценка качества
Внутри `train_and_evaluate_adaptive_ensembles` вычисляются:
- MAE, RMSE, R2
- медианная абсолютная ошибка
- клинические метрики: доля ошибок < 5 мм и < 10 мм
- максимальная ошибка, число выбросов (>20 мм)

Это важно вынести в диссертацию как:
- “инженерный набор метрик”
- “клинические пороги качества”

## 8. Что именно сохраняется в `models/adaptive_ensemble.pkl`
Из API видно, что объект содержит:
- `models`: словарь `target_name -> модель`
- `scaler`: обученный scaler
- `feature_names`: список признаков, которые нужно подавать модели

Для диссертации:
- описать состав артефакта и аргументировать, почему это обеспечивает воспроизводимость.

## 9. Различия в числах метрик между документами
В проекте присутствуют несколько наборов метрик:
- `README.md`: Average MAE = 2.140 мм
- `docs/MODEL_TECHNICAL_DOCUMENTATION.md`: Average MAE = 2.140 мм
- `docs/archive/README_ENHANCED_PRODUCTION.md`: Phase 1 MAE = 2.740 мм
- `results/final_model_comparison_report.md`: Adaptive_Ensemble Val MAE = 1.706 мм

Это означает, что:
- эксперименты проводились на разных разбиениях/наборе целей/наборе признаков;
- часть документов относится к другой постановке (например, 9 точек vs 2 центра, 78 целей vs 6 целей).

В диссертации рекомендуется:
- завести таблицу “эксперимент → датасет → цели → признаки → метрика → разбиение”
- явно указать, какие метрики относятся к production-ветке.
