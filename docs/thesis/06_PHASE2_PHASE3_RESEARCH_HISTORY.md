# 06. История Phase 2 и Phase 3 (по артефактам и архивной документации)

## 0. Важное уточнение по исходникам
В текущей рабочей копии репозитория:
- **нет** директории `enhanced_models/phase2` и кода, который в ряде документов описан как Phase 2.
- однако **есть**:
  - `results/phase2/*.csv` — численные результаты Phase 2;
  - `docs/archive/README_ENHANCED_PRODUCTION.md` — подробное текстовое описание Phase 2;
  - `docs/archive/PHASE3_FINAL_CONCLUSIONS.md` — выводы по Phase 3;
  - `results/phase3/*` — исследовательские скрипты Phase 3.

Поэтому Phase 2 ниже описывается как «восстановленная фаза» по результатам/архивам.

## 1. Phase 2: Enhanced Production (восстановление по отчётам)

### 1.1. Заявленная цель Phase 2
Согласно `docs/archive/README_ENHANCED_PRODUCTION.md`, Phase 2 пыталась улучшить Phase 1 за счёт:
- динамической адаптации весов ансамбля (Dynamic Adaptive Ensemble);
- расширенного feature engineering (134 дополнительных признака);
- кластеризации пациентов.

### 1.2. Заявленные метрики (из README_ENHANCED_PRODUCTION.md)
Там указано:
- Phase 1 Average MAE: 2.740 mm
- Phase 2 Average MAE: 2.496 mm
- Improvement: +8.9%

### 1.3. Фактические CSV результаты Phase 2

#### 1.3.1. `results/phase2/multivariate_displacement_results.csv`
Содержит результаты нескольких моделей, например:
- `MultiTask_RandomForest` Overall MAE ≈ 2.893
- `MultiTask_Lasso` Overall MAE ≈ 2.670

Это показывает, что Phase 2 включала поиск многомерных/многозадачных постановок (multi-task), и как минимум линейные модели с регуляризацией давали конкурентные результаты.

#### 1.3.2. `results/phase2/dynamic_adaptive_ensemble_results.csv`
Содержит поцелевые метрики для `Dynamic_Adaptive_Ensemble` и `Standard_Adaptive_Ensemble`.
В таблице видно, что метрики почти идентичны (Improvement ≈ 0), что согласуется с `phase2_enhancement_summary.csv` (Status: ❌ No Change).

Возможные причины «No Change» (гипотезы для диссертации):
- динамический механизм не отличался от стандартного из-за одинаковых весов/кластеров;
- недостаточно данных для устойчивой кластеризации;
- ошибка экспериментального протокола (например, пересечение train/val или некорректное применение динамических весов).

### 1.4. Как корректно описать Phase 2 в диссертации
Рекомендуемая формулировка:
- Phase 2 — фаза инженерного усиления (feature engineering + персонализация), которая была сформулирована и частично экспериментально подтверждена по отчётам.
- В текущей поставке отсутствуют исходники Phase 2, поэтому воспроизводимость Phase 2 ограничена артефактами результатов и документами.

Это честно и академически корректно.

## 2. Phase 3: Research approaches (нейросети, multitask, uncertainty)

### 2.1. Что реально есть в репозитории
В `results/phase3/` присутствуют:
- `neural_network_ensemble.py`
- `multitask_learning_predictor.py`
- `uncertainty_quantification_predictor.py`
- `run_phase3_research.py`
- `compare_phase3_results.py`
- CSV файлы с результатами

Это означает, что Phase 3 как минимум была реализована в виде runnable исследовательских скриптов.

### 2.2. Как устроен запуск Phase 3
Файл `results/phase3/run_phase3_research.py`:
- последовательно запускает 3 исследовательских скрипта через `subprocess.run`;
- меряет время;
- собирает summary `phase3_research_summary.txt`;
- при достаточном числе успешных прогонов запускает сравнение.

### 2.3. Проблема воспроизводимости Phase 3 в текущих артефактах
`results/phase3/phase3_research_summary.txt` показывает, что в одном из прогонов все 3 скрипта завершились как FAILED.

При этом в `docs/archive/PHASE3_FINAL_CONCLUSIONS.md` описаны успешные метрики (MAE 2.736 и т.п.).

Следовательно:
- либо были успешные прогоны в другой среде/на другом наборе данных;
- либо summary относится к запуску без необходимых входных файлов (в `run_phase3_research.py` проверяются `data/vybor_unified_features.csv` и `data/kits19_medical_grade_features.csv`).

### 2.4. Как описать Phase 3 в диссертации
Phase 3 логично описывать как:
- исследовательская проверка гипотезы «глубокое обучение улучшит качество»;
- реализация трёх направлений:
  - ансамбль нейросетей
  - multitask learning
  - uncertainty quantification
- вывод: традиционные методы + feature engineering (Phase 2) оказались эффективнее при текущем объёме данных.

## 3. Сопоставление фаз (как оформить таблицу для диссертации)
Рекомендуется использовать таблицу:
- Фаза
- Постановка задачи (targets)
- Число признаков
- Модельный класс
- Датасет/разбиение
- MAE/R2/<5mm/<10mm
- Статус (production/research)
- Воспроизводимость (есть ли код + артефакты)

И отдельно отметить:
- Phase 1 — воспроизводим полностью по коду и артефакту `adaptive_ensemble.pkl`.
- Phase 2 — воспроизводим частично (результаты есть, исходников нет).
- Phase 3 — воспроизводим условно (код есть, но нужны входные данные и зависимости).
