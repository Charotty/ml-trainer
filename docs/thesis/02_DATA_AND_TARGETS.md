# 02. Данные и целевые переменные (Data & Targets)

## 1. Источники данных
По документации и коду используются/упоминаются следующие источники:
- **DICOMS** — медицинские изображения и метаданные, из которых извлекаются геометрические/анатомические признаки.
- **Vybor** — унифицированные клинические табличные данные.
- **KiTS19** — внешний набор данных (в проекте используется как источник дополнительных признаков и/или исследований).

Фактические файлы в текущей копии:
- `data/processed/train.csv`
- `data/processed/validation.csv`
- (для baseline-пайплайна) `data/processed/test.csv` + `data/processed/feature_names.json` + `data/processed/target_names.json`
- `data/integrated_master_dataset.csv` (упоминается в документации/поиске)

## 2. Что именно предсказывается (targets)

### 2.1. Phase 1 integrated ensemble (6 целей)
В `models/phase1/adaptive_ensemble.py` задан список:
- `kidney_left_delta_x`, `kidney_left_delta_y`, `kidney_left_delta_z`
- `kidney_right_delta_x`, `kidney_right_delta_y`, `kidney_right_delta_z`

Смысл:
- `delta_x` — боковое смещение (левая/правая ось)
- `delta_y` — передне-заднее смещение
- `delta_z` — кранио-каудальное смещение (голова-ноги)

Единицы: миллиметры.

### 2.2. Общий baseline pipeline (много целей)
В `scripts/training/train_all_models.py` загружаются:
- `feature_names.json`
- `target_names.json`

В отчёте `results/final_model_comparison_report.md` фигурирует:
- `Targets: 78` для RF/XGB
- `Targets: 6` для Adaptive_Ensemble

Это означает, что в проекте существуют (или существовали) эксперименты, где модель предсказывает значительно более широкий набор координат/дельт (например, верх/середина/низ, и/или множество производных).

Для диссертации это можно оформить как:
- “широкая постановка задачи” (многомерный таргет)
- “сжатая production-постановка” (6 delta для центров левой/правой почки)

## 3. Структура признаков (features)

### 3.1. Phase 1 integrated ensemble
Файл: `models/phase1/adaptive_ensemble.py`

Входной базовый набор (`required_features`) включает:
- относительные координаты центров почек `*_center_*_rel`;
- размеры почек `*_length_mm`, `*_volume_cm3`;
- геометрию тела `body_width_mm`, `body_depth_mm`, `body_area_mm2`;
- расстояния до опорных структур (`*_to_spine_distance`, `*_to_body_center_distance`);
- координаты “центра позвоночника” и “центра масс тела” (используются для относительных признаков).

Далее автоматически создаются:
- инженерные признаки (`engineered_features`, 13)
- cross-features (`cross_features`, 15)

### 3.2. AdvancedFeatureEngineer как альтернативная ветка
Файл: `src/features/advanced_features.py`

Там присутствуют дополнительные потенциальные признаки:
- относительные координаты в “сырых” мм (`kidney_left_center_x_mm` и т.п.)
- дистанции, углы, отношения размеров
- признаки состава тела (fat/bone ratios)
- признаки возраста/антропометрии

Важно: этот модуль не является “авторитетной” частью production API (FastAPI использует feature engineering из `AdaptiveEnsembleTrainer`). Но для диссертации полезно показать, как развивалась идея расширения признаков.

## 4. Качество данных и пропуски

### 4.1. Как обрабатываются пропуски
В разных ветках:
- `models/phase1/adaptive_ensemble.py` использует `SimpleImputer(strategy='median')`, но при этом в показанном участке подготовки `X` фактически берётся напрямую и масштабируется.
- `scripts/training/train_all_models.py` использует кастомный `MedianImputerKeepAll(fill_value_if_all_nan=0.0)` и масштабирование `StandardScaler`.

Диссертационный вывод:
- наличие стабильного imputing — критично, чтобы количество признаков не «плавало» и не ломало train/inference.

### 4.2. Защита от leakage
В `scripts/training/train_all_models.py` есть явная защита:
- если таргеты начинаются с `delta_`, то из входа исключаются признаки с `_lateral`.

Это важно описать в диссертации как инженерный контроль утечки целевой информации.

## 5. Рекомендации как оформить в диссертации
- Чётко разделить постановки задачи:
  - production (6 целей)
  - расширенная исследовательская (много целей)
- Обязательно включить раздел:
  - система единиц
  - смысл осей
  - типичные диапазоны значений
- Отдельно выделить блок:
  - пропуски
  - утечки
  - детерминизм разбиений (`random_state=42`)
