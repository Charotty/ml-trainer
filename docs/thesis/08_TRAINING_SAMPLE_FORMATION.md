# Формирование обучающей выборки

## Исходная постановка и переход к production

В исходном исследовании, описанном в диссертации, обучающая выборка формировалась из **100 пациентов**, для каждого из которых выполнялись парные измерения положения почек на мультиспиральной компьютерной томографии (МСКТ) в положении **лёжа на спине** и **в латеральном декубитусе**. Целевой величиной служило трёхмерное смещение центроида почки (ΔX, ΔY, ΔZ, мм), рассчитанное как разность координат между двумя положениями.

При переносе модели в программную систему предсказания смещения (production-пайплайн) была сохранена та же клиническая логика — обучение только на пациентах с **подтверждённой парой измерений** и полным набором целевых переменных, — но ужесточены критерии включения в выборку и явно разделены роли клинических и вспомогательных источников данных.

---

## Критерии формирования production-выборки

Исходным документом для клинических меток служит таблица «Смещение - конечное -12» (экспорт в `data/vybor_from_xlsx.csv` скриптом `build_vybor_from_xlsx.py`). В production-контуре применяются следующие правила:

1. **Включены только пациенты с полностью заполненными измерениями смещения** — для каждого из шести таргетов (`kidney_left_delta_{x,y,z}`, `kidney_right_delta_{x,y,z}`) должны быть заданы числовые значения без пропусков.

2. **Исключены случаи с отсутствующими или неполными координатами** — строки с незавершённым расчётом смещения по средней трети почки (incomplete middle-point deltas) не попадают в обучающий набор. Автоматическая фильтрация выполняется при сборке CSV (`require_complete_targets=True`).

3. **Итоговая обучающая выборка составила 87 пациентов** из 100 исходных записей диссертационной таблицы; **13 наблюдений** отбраковано из‑за неполноты целевых переменных.

Таким образом, production-модель обучается не на «максимально широкой» таблице, а на **строго валидированном подмножестве**, пригодном для регрессии по всем шести выходам без имputation целевой переменной.

Оценка качества модели выполняется на тех же 87 пациентах протоколом **GroupKFold(5) с группировкой по пациенту** (out-of-fold предсказания), что обеспечивает честную оценку обобщающей способности и сопоставимость с диссертационной логикой перекрёстной проверки при более строгом разбиении по идентификатору случая.

## Почему na_spine, na_boku и KiTS19 не являются обучающими примерами

Помимо клинической таблицы Vybor в проекте используются три крупных вспомогательных массива томографических данных:

| Источник | Объём | Содержание сканов |
|----------|-------|-------------------|
| **na_spine** | 137 записей | МСКТ «на спине» (supine), без парных клинических δ |
| **na_boku** | 109 записей | МСКТ «на боку» (lateral), без парных клинических δ |
| **KiTS19** | 210 записей | внешняя когорта КТ; proxy-метки смещения не являются клинической истиной |

**Ни один из этих источников не добавляет строк в обучающую выборку регрессии** в production-режиме `clinical_honest` / `labeled_only`. Это принципиальное методическое отличие от подходов, при которых внешние датасеты включаются в `y` как псевдо-метки или proxy-targets.

### Причины исключения из обучающих примеров

**1. Отсутствие парного клинического эталона.**  
Для na_spine и na_boku имеется только **одно положение тела на скан** (либо supine, либо lateral). В таблицах нет одновременно измеренной пары «лёжа + на боку» у того же пациента с верифицированным смещением в мм. Следовательно, эти записи **не могут служить самостоятельными примерами** для обучения модели вида «supine-признаки → величина Δ».

**2. Несопоставимость KiTS19 с клинической задачей.**  
KiTS19 — набор КТ почечных образований иного клинического контекста. Даже при наличии числовых колонок proxy-δ они не эквивалентны измерениям смещения почки при смене положения тела у операционных пациентов. Использование KiTS19 как обучающих таргетов приводит к **смещению распределения** `y` и завышению оптимистичных метрик — что подтверждено сравнением proxy-weighted обучения с честным GKF-OOF на 87 клинических случаях.

**3. Разделение «метка» и «контекст популяции».**  
В программной системе введено явное разграничение:
- **обучающий пример** = один клинический пациент с измеренным Δ;
- **популяционный контекст** = статистика большой когорты однотипных сканов без индивидуальной метки смещения.

## Использование вспомогательных данных: только популяционные характеристики

Вспомогательные массивы na_spine, na_boku и (опционально) KiTS19 подключаются через модуль когортных трендов `NaTrendStore` (`src/features/na_trend_features.py`) **исключительно как источник популяционных характеристик**, а не как дополнительные строки в матрице обучения.

Для каждого клинического пациента из выборки 87 к расчётным supine-признакам добавляются:

- **приоры сдвига когорты** — разность медианных положений почки между lateral-когортой (na_boku) и supine-когортой (na_spine): `na_pop_shift_{side}_{axis}`;
- **нормированные отклонения от supine-популяции** — z-score и процентиль клинических признаков относительно распределения na_spine: `na_sup_z_*`, `na_sup_pct_*`;
- при экспериментальном включении KiTS19 — аналогичные отклонения относительно внешней когорты и медианы proxy-δ **на уровне всей популяции** (константы `kits_cohort_median_*`), без привязки lateral-координат конкретного пациента по имени.

Критически важно: **не выполняется** подстановка per-patient lateral-координат из na_boku в строку клинического пациента и **не выполняется** дополнение пропущенных объёмов почек из вспомогательных таблиц в production-сборке (`--no-boku`). Это исключает скрытую утечку информации о lateral-положении в признаки модели, предназначенной работать **только по supine-скану**.

## Методическое значение различия

Разделение «87 клинических обучающих примеров» и «вспомогательные когорты без y» обеспечивает:

1. **Сопоставимость с диссертацией по смыслу задачи** — предсказание клинически измеренного смещения при смене положения тела.
2. **Честность метрик** — GKF-OOF на 87 пациентах отражает реальную ошибку (~8,4 мм по среднему MAE), в отличие от завышенных оценок при включении proxy-меток или in-sample holdout.
3. **Расширяемость системы** — новые МСКТ-потоки (na_spine, na_boku, внешние базы) могут обогащать **статистику популяции**, не размывая определение целевой переменной.
4. **Прозрачность для клинического применения** — на входе inference остаётся один supine-скан; lateral-данные вспомогательных когорт не подменяют отсутствующее клиническое измерение у конкретного пациента.

Итог: **обучающая выборка production-модели — это 87 верифицированных клинических пар измерений**; na_spine, na_boku и KiTS19 — **не обучающие примеры**, а **референсные популяции** для формирования когортных статистических признаков. Данное разграничение является одним из ключевых методических отличий программной реализации от наивного объединения всех доступных томографических таблиц в единый «большой» датасет.
