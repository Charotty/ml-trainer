# 🧠 Pipeline обработки КТ для извлечения анатомических и геометрических признаков (включая координаты почек)

## 🎯 Цель

Разработать эффективный pipeline обработки КТ-данных, который извлекает полный набор признаков (52+), включая координаты почек, **без использования полной 3D сегментации и без загрузки всего объёма в оперативную память**.

Pipeline должен быть:

* memory-efficient (работа в ограниченной RAM)
* масштабируемым
* пригодным для ML-задач (лапароскопия, установка троакаров)

---

## 📥 Входные данные

* DICOM серия (папка со срезами)
* Метаданные из DICOM:

  * PixelSpacing
  * SliceThickness
  * ImagePositionPatient
  * PatientPosition
  * PatientID, StudyInstanceUID и др.

---

## ⚙️ Основные требования к архитектуре

### 1. Streaming обработка (ключевое требование)

Pipeline должен:

* обрабатывать КТ **по одному срезу (slice-by-slice)** или небольшими блоками (patch-based)
* НЕ загружать весь объём в память
* НЕ хранить полные 3D маски

---

### 2. Lazy loading / on-demand чтение

Использовать:

* чтение DICOM по одному файлу
* или chunked форматы (например Zarr)

---

### 3. Однопроходная обработка (single-pass)

Все признаки должны вычисляться:

* за **один проход по данным**
* без повторной загрузки КТ

---

## 🧩 Этапы pipeline

### 🔹 Этап 1: Загрузка и нормализация

* чтение DICOM срезов (сортировка по Z)
* преобразование в HU (Hounsfield Units)
* извлечение spacing (mm)

---

### 🔹 Этап 2: Извлечение метаданных

* patient_id, study_uid
* возраст, пол, вес, рост
* позиция пациента
* дата исследования

---

### 🔹 Этап 3: Глобальные маски (лёгкие)

На каждом срезе вычислять:

* маска тела (threshold HU)
* маска жира
* маска костей

⚠️ Маски НЕ сохраняются — используются только локально

---

### 🔹 Этап 4: Геометрия тела

На каждом срезе:

* ширина тела
* глубина
* площадь

Агрегация:

* median / mean по всем срезам

---

### 🔹 Этап 5: Центр масс тела

В потоковом режиме:

* суммирование координат
* подсчёт количества точек

Результат:

* body_com_x/y/z

---

### 🔹 Этап 6: Детекция позвоночника

Методы:

* threshold по костной ткани
* connected components
* фильтрация по положению (центр тела)

Результат:

* spine_center_x/y/z

---

### 🔹 Этап 7: Расстояния до кожи

На каждом срезе:

* определить границы тела
* измерить расстояния от позвоночника:

  * left / right / anterior / posterior

Агрегация:

* median

---

## 🫘 Этап 8: Детекция почек (без сегментации)

### ⚠️ Критически важно:

НЕ использовать тяжёлые модели (например полную сегментацию через TotalSegmentator)

---

### Подход:

Использовать lightweight фильтрацию:

* HU диапазон (пример: 30–300)
* spatial constraints:

  * по Z (область живота)
  * относительно позвоночника
* connected components

---

### Разделение:

* левая почка: x < spine_center_x
* правая почка: x > spine_center_x

---

## 📍 Этап 9: Извлечение координат почек (streaming)

### Для каждой почки:

#### 1. Центр (middle)

* вычисляется как центроид (накопление сумм)

#### 2. Верхняя точка (upper)

* минимальный z, где есть почка

#### 3. Нижняя точка (lower)

* максимальный z

---

### X/Y координаты:

* считаются только на соответствующих срезах:

  * верхний
  * средний
  * нижний

---

### Объём:

* суммирование voxel_count × voxel_volume

---

### Длина:

* (z_max - z_min) × slice_thickness

---

## 💾 Этап 10: Агрегация без хранения данных

Pipeline НЕ должен:

* хранить массив координат
* хранить 3D маски

Pipeline должен:

* хранить только агрегаты:

  * суммы
  * счётчики
  * min/max

---

## 📤 Выходные данные

Таблица признаков (52+ колонок):

* идентификационные
* демографические
* анатомические
* геометрические
* координаты почек
* объёмы
* расстояния

Формат:

* CSV / Parquet / DataFrame

---

## 🚀 Оптимизации (обязательные)

* downsampling (опционально)
* integer arithmetic где возможно
* отказ от хранения промежуточных данных
* использование NumPy без копирования
* минимизация аллокаций

---

## ❗ Ограничения

Pipeline НЕ должен:

* использовать > RAM лимита
* требовать GPU
* использовать full-volume segmentation

---

## 🧠 Итоговая концепция

Pipeline должен работать по принципу:

> "прочитал срез → обработал → обновил статистику → забыл"

А НЕ:

> "загрузил всё → сегментировал → потом посчитал"

---

## 🎯 Применение

* планирование лапароскопии
* расчёт установки троакаров
* ML модели для навигации в хирургии
