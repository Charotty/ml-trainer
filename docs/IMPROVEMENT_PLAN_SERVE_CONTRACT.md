# План: контракт артефакта и серва (train/serve gap)

Реализация не начата. Документ фиксирует найденные расхождения и порядок работ.
Диагностика воспроизводится одной командой:

```bash
python scripts/validation/diagnose_train_serve_gap.py \
  --case 'Zhiltsova=3c2c292f-49d7-474b-86f5-6b74746c17dc' \
  --case 'Rublevskaya=4a44f76c-95a2-46d4-82d7-f7ed1e3cd534'
```

## Ограничения

- Переобучение — **отдельный этап**, в этот план не входит. Все задачи ниже меняют
  только сохранение артефакта и путь инференса.
- Целевая метрика Excel и система координат не меняются.
- Значения Excel не выдумываем; медианы когорты не подставляем ради покрытия 100%.
- Не коммитим без отдельной просьбы.

## Что измерено

`models/adaptive_ensemble_clinical_honest.pkl`, 129 признаков, n=120 строк
(102 двусторонних + 18 односторонних).

| Наблюдение | Значение |
|---|---|
| Реально информативных признаков на серве, Жильцова | 70/129 (54%) |
| То же, Рублевская | 42/129 (33%) |
| NaN у **каждого** пациента (энкодер не сохранён) | 10/129 |
| Аффинные дубликаты `na_sup_z_*` / `na_sup_pct_*`, \|r\| > 0.999999 | 42/129 |
| Константы (6 × `na_pop_shift_*` ≈ 1e-16 и др.) | 8/129 |
| За пределами train min/max, Жильцова / Рублевская | 48 / 44 |
| Доля важности на OOD-признаках | 31–39% |
| Доля важности на импьютированных NaN, Рублевская, левые таргеты | 27–40% |
| Признаков в клипе \|z\|=12, Рублевская | 40 |

Честный вложенный GroupKFold-OOF: 8.40–8.52 мм. Историческая цифра 2.14 мм —
in-sample/протекающая, как эталон не используется (`docs/MODEL_CARD.md`).

## Ключевая находка по латеральности

`kidney_*_center_x_rel == 0.0` — де-факто маркер единственной почки в обучении:
15/18 односторонних строк против 0/102 двусторонних (у тех диапазон [−11.6, +11.9]).
Маркер возникает потому, что Excel-адаптер при отсутствии контралатеральной почки
ставит «позвоночник» в позицию самой почки.

На серве маркер уничтожается дважды:

1. `harmonize_ct_to_clinical_frame` при отсутствии любой из шести координат делает
   ранний `return out` — не выдаёт `_rel`, `spine_center_*`, `body_com_*` и
   `*_to_spine_distance` даже для **здоровой** стороны.
2. Импьютер подставляет медиану двухпочечной когорты: `x_rel → −1.45` вместо 0.0,
   `kidney_left_volume_cm3 → 157.7`, `kidney_distance_lr → 5.8`, `volume_asymmetry → 6.0`.

Отдельно: «почки нет» и «почку не нашли» неразличимы. В обучении из 11 right-only
у 9 контралатеральных признаков нет вообще, у 2 почка есть, но смещение не измеряли.
В `extract_kidney_features_from_ts_output` пустая маска, отсутствующий файл и сбой
сегментации дают идентичный результат.

## Регресс-тест

**Рублевская — обучающий пациент** (строка 104 `data/vybor_from_xlsx.csv`,
единственная правая почка, `has_previous_surgery = 1.0`, правый ΔZ = +7.0).
Серв на ней выдаёт −28.5 мм. Значит критерий однозначный: после исправления серва
правый ΔZ обязан подойти к +7.0. Если не подошёл — проблема в модели, а не в подаче.

Жильцова остаётся вторым контрольным кейсом (двусторонняя, текущий MAE 6.96 мм).

## Этапы

| # | Задача | Приёмка | Затрагивает |
|---|--------|---------|-------------|
| 1 | Сохранять `categorical_encoder`, `z_driver_names`, версии схемы в payload | В pkl есть энкодер; загрузчик падает на артефакте без него, а не работает молча | `scripts/data/train_clinical_honest.py`, `src/models/runtime.py` |
| 2 | Проверка контракта при загрузке модели | Число NaN-у-всех признаков == 0; тест на артефакте-заглушке | `src/models/runtime.py`, `tests/` |
| 3 | Трёхзначные флаги латеральности `kidney_{side}_present`: `present` / `absent` / `not_assessed` | Флаг доступен в QA-UI и доезжает до `predict`; Рублевская помечается `right=present`, `left=absent` | `src/features/phase1_schema.py`, `src/api/cases/features_service.py`, `frontend/public/` |
| 4 | Различать пустую маску и отсутствующий файл в извлечении | В `extraction_raw.json` есть причина отсутствия почки | `scripts/inference/extract_from_dicom.py` |
| 5 | Убрать ранний выход из `harmonize_ct_to_clinical_frame`: ветка солитарной почки | Для Рублевской заполнены `kidney_right_center_*_rel`, `spine_center_*`, `body_com_*`; `x_rel == 0.0` как в обучении | `src/features/ct_geometry.py` |
| 6 | Отказ по стороне вместо числа: `null` + причина для `absent`, флаг достоверности для `not_assessed` | Левые таргеты Рублевской не возвращают чисел | `src/api/cases/router.py`, `src/api/cases/predictor.py` |
| 7 | Расширить `assess_prediction_sanity`: доля импьютированных признаков по таргету, а не только \|Δ\| > 80 мм | Порог срабатывает на 40.5% важности на NaN | `src/api/cases/predictor.py` |
| 8 | Вычистить 42 зеркала и 8 констант из контракта признаков | `feature_names` без `na_sup_*` и `na_pop_shift_*` | требует переобучения — **следующий этап** |

Пункты 1–7 проверяются без переобучения. Пункт 8 и всё, что меняет распределение
признаков (анатомический якорь по S1 вместо вырожденного нуля, нативная работа с NaN
через `HistGradientBoostingRegressor`, трактовка объёма при компенсаторной гипертрофии —
у Рублевской 265.6 см³ против медианы 157.7), выносится в этап переобучения.
