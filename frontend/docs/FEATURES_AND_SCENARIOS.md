# CT Workbench — фичи и пользовательские сценарии

Каталог функциональности (F-xxx) и сценариев использования (US-xx) для браузерного интерфейса CT Workbench.

Связанные документы: [PRD.md](PRD.md), [ARCHITECTURE.md](ARCHITECTURE.md).

---

## 1. Персоны

| Персона | Цель | Типичные задачи |
|---------|------|-----------------|
| **Врач-уролог / хирург** | Получить прогноз смещения почек перед/во время планирования операции | Загрузить КТ, проверить точки, получить ΔX/Y/Z |
| **Исследователь** | Валидация модели, сбор данных для диссертации | Batch-кейсы, отчёты, сравнение с Ridge+LOO |
| **Инженер ML** | Настройка пайплайна, отладка extraction | Coverage, логи worker, переключение model bundle |

---

## 2. Шаблон описания фичи

Каждая фича ниже содержит:

- **Описание** — что делает
- **Зачем** — клиническая/научная ценность
- **Входы / выходы**
- **Приоритет** — MVP / v1.1 / v2
- **Зависимости**
- **Критерии готовности** (acceptance criteria)

---

## 3. Каталог фич

### F-001 — Загрузка DICOM

| Поле | Значение |
|------|----------|
| **Описание** | Пользователь загружает zip-архив или папку DICOM supine-исследования через drag-and-drop или выбор файла. |
| **Зачем** | Точка входа в систему без ручного ввода 23 признаков с нуля. |
| **Входы** | Файл `.zip` или набор `.dcm` |
| **Выходы** | `case_id`, статус `uploaded`, файлы в `data/cases/{id}/dicom/` |
| **Приоритет** | MVP |
| **Зависимости** | `POST /cases/{id}/upload`, хранилище кейсов |
| **Критерии готовности** | Zip до N ГБ загружается; при битом архиве — понятная ошибка; DICOM сохранён на диск |

---

### F-002 — Автовыбор серии (abdomen supine)

| Поле | Значение |
|------|----------|
| **Описание** | Система анализирует DICOM-метаданные и выбирает основную серию КТ живота в положении supine. |
| **Зачем** | Исключить ошибочный выбор скаутов, локализаторов, повторных серий. |
| **Входы** | DICOM в папке кейса |
| **Выходы** | `selected_series_uid`, предупреждения в `meta.json` |
| **Приоритет** | MVP |
| **Зависимости** | `scripts/inference/dicom_prep.py` |
| **Критерии готовности** | Для типичного abdominal CT выбирается серия с наибольшим числом срезов; при неоднозначности — warning в UI |

---

### F-003 — Async extraction job + прогресс

| Поле | Значение |
|------|----------|
| **Описание** | Запуск извлечения признаков в фоне с отображением этапа (dcm2niix → segmentation → features). |
| **Зачем** | Extraction занимает минуты; нельзя блокировать браузер. |
| **Входы** | `POST /cases/{id}/analyze` |
| **Выходы** | `job_id`, polling `GET /status` с `progress_pct`, `stage` |
| **Приоритет** | MVP |
| **Зависимости** | Worker, Redis/FS queue |
| **Критерии готовности** | UI обновляет прогресс ≥ каждые 5 с; при падении worker — status `failed` + текст ошибки |

---

### F-004 — Автозаполнение 23 BASE_FEATURES

| Поле | Значение |
|------|----------|
| **Описание** | После extraction форма заполняется каноническими полями из `phase1_schema.BASE_FEATURES`. |
| **Зачем** | Минимизировать ручной труд; обеспечить паритет с обучением модели. |
| **Входы** | Результат `extract_from_dicom.py` |
| **Выходы** | `base_features.json`, `features.json` (111 полей) |
| **Приоритет** | MVP |
| **Зависимости** | `phase1_schema.normalize_dataframe`, `AdaptiveEnsembleTrainer._build_feature_matrix` |
| **Критерии готовности** | ≥ 80% BASE_FEATURES непустые для типичного кейса; missing — список в UI |

---

### F-005 — Ручная правка координат почек (QA)

| Поле | Значение |
|------|----------|
| **Описание** | Пользователь редактирует 6 полей `kidney_*_center_*_rel` и опорные `spine_center_*`, `body_com_*`. |
| **Зачем** | Компенсация ошибок сегментации; клинически критичные точки. |
| **Входы** | Текущие `base_features`, новые значения |
| **Выходы** | `manual_overrides.json`, пересчитанные производные признаки |
| **Приоритет** | MVP |
| **Зависимости** | `PATCH /features/manual`, F-004 |
| **Критерии готовности** | Правка сохраняется; audit log с timestamp; predict использует обновлённые значения |

---

### F-006 — Ручной ввод lordosis / abd wall / spans

| Поле | Значение |
|------|----------|
| **Описание** | Опциональные поля: `lumbar_lordosis_deg`, `s1_plate_tilt_deg`, `abd_wall_thickness_mm`, `kidney_*_z_span_supine_mm`, `kidney_*_y_span_supine_mm`. |
| **Зачем** | Улучшение прогноза по осям Y и Z (наибольшая ошибка модели). |
| **Входы** | Измерения с КТ вручную |
| **Выходы** | Обновлённые axis/anatomical признаки |
| **Приоритет** | v1.1 |
| **Зависимости** | F-005, `displacement_axis_features` |
| **Критерии готовности** | Поля отображаются в «расширенной» секции формы; влияние на predict проверяемо |

---

### F-007 — Показатель качества (feature coverage %)

| Поле | Значение |
|------|----------|
| **Описание** | Процент заполненных признаков среди 111 production + список missing. |
| **Зачем** | Предупредить о ненадёжном прогнозе до нажатия Predict. |
| **Входы** | `features.json` |
| **Выходы** | `coverage_pct`, `missing_features[]`, цветовой индикатор (green/yellow/red) |
| **Приоритет** | v1.1 |
| **Зависимости** | `validate_base_features`, F-004 |
| **Критерии готовности** | Coverage < 80% — блокирующий warning; < 90% — жёлтый warning |

---

### F-008 — Прогноз 6 смещений (мм)

| Поле | Значение |
|------|----------|
| **Описание** | ML-инференс: `kidney_left/right_delta_{x,y,z}` в миллиметрах. |
| **Зачем** | Основной результат продукта для клиники и AR. |
| **Входы** | 111 признаков, `adaptive_ensemble_clinical_honest.pkl` |
| **Выходы** | `prediction.json` с 6 float |
| **Приоритет** | MVP |
| **Зависимости** | `pipeline.predict_targets`, `NaTrendStore`, F-004 |
| **Критерии готовности** | Все 6 таргетов — конечные числа; время < 2 с; model_id в metadata |

---

### F-009 — Подсветка оси Z

| Поле | Значение |
|------|----------|
| **Описание** | В таблице прогноза ось Z и таргеты `*_delta_z` выделены визуально (наибольшая ожидаемая ошибка ~11 мм). |
| **Зачем** | Направить внимание врача на слабое место модели. |
| **Входы** | `prediction.json` |
| **Выходы** | UI-подсветка, tooltip с ссылкой на валидацию |
| **Приоритет** | v1.1 |
| **Зависимости** | F-008 |
| **Критерии готовности** | Z-строки отличимы; tooltip ссылается на `docs/thesis/10_CLINICAL_VALIDATION_AND_COMPARISON.md` |

---

### F-010 — Сравнение до/после ручной правки

| Поле | Значение |
|------|----------|
| **Описание** | Показать Δ прогноза: auto-only vs after manual QA. |
| **Зачем** | Оценить влияние ручной коррекции; обучение пользователя. |
| **Входы** | Два прогона predict (snapshot до/после PATCH) |

| **Приоритет** | v1.1 |
| **Зависимости** | F-005, F-008 |
| **Критерии готовности** | Diff в мм по каждой оси; сохранение обеих версий в кейсе |

## 4. Пользовательские сценарии

### US-01 — Быстрый прогноз по загруженному КТ

| Поле | Значение |
|------|----------|
| **Цель** | Получить 6 значений смещения с минимумом действий |
| **Персона** | Врач |
| **Предусловия** | Модель обучена локально; браузер открыт на Dashboard |
| **Шаги** | 1. Создать кейс → 2. Загрузить DICOM zip → 3. «Анализировать» → 4. Дождаться `features_ready` → 5. «Прогноз» → 6. Просмотреть таблицу Δ |
| **Результат** | `prediction.json`, статус `predicted` |
| **Альтернативы** | Extraction failed → сообщение + предложение ручного ввода BASE; coverage < 80% → warning |
| **Фичи** | F-001, F-002, F-003, F-004, F-008 |

---

### US-02 — Исправление автосегментации вручную

| Поле | Значение |
|------|----------|
| **Цель** | Исправить неверные координаты почки после плохой сегментации |
| **Персона** | Врач |
| **Предусловия** | Кейс в статусе `features_ready` или `qa_pending` |
| **Шаги** | 1. Открыть QA-форму → 2. Сравнить значения с КТ (внешний viewer или F-016) → 3. Изменить `kidney_left_center_*_rel` → 4. Сохранить → 5. Проверить coverage |
| **Результат** | `manual_overrides.json` с записью правки |
| **Альтернативы** | Нет viewer на MVP — ввод по числам с внешнего PACS |
| **Фичи** | F-005, F-007 |

---

### US-03 — Повторный прогноз после правки

| Поле | Значение |
|------|----------|
| **Цель** | Увидеть, как ручная правка изменила прогноз |
| **Персона** | Врач / исследователь |
| **Предусловия** | US-02 выполнен |
| **Шаги** | 1. «Прогноз» повторно → 2. Сравнить с предыдущим (F-010) → 3. Экспорт отчёта |
| **Результат** | Новый `prediction.json`, diff в UI |
| **Альтернативы** | Изменение < 0.5 мм — показать «стабильный прогноз» |
| **Фичи** | F-008, F-010, F-017 |

---

### US-04 — Экспорт для AR-навигации

| Поле | Значение |
|------|----------|
| **Цель** | Передать прогноз в Unity/HoloLens |
| **Персона** | Инженер |
| **Предусловия** | US-01 или US-03 завершён |
| **Шаги** | 1. Открыть кейс → 2. «Экспорт AR» → 3. Скачать `ar_export.json` → 4. Импорт в Unity |
| **Результат** | Файл по ENHANCED_JSON_CONTRACT |
| **Альтернативы** | v2 only — на MVP использовать `report.json` |
| **Фичи** | F-018, F-017 |

---

### US-05 — Пакетная обработка когорты

### US-06 — Отчёт для диссертации

| Поле | Значение |
|------|----------|
| **Цель** | Получить документ для главы 3 диссертации |
| **Персона** | Исследователь |
| **Предусловия** | Кейс `predicted` |
| **Шаги** | 1. «Сформировать отчёт» → 2. PDF или JSON → 3. Включить в приложение диссертации |
| **Результат** | `report.pdf` / `report.json` |
| **Альтернативы** | Только JSON на MVP |
| **Фичи** | F-015, F-017 |

---

### US-07 — Диагностика низкого coverage

| Поле | Значение |
|------|----------|
| **Цель** | Понять, каких признаков не хватает для надёжного прогноза |
| **Персона** | Инженер |
| **Предусловия** | `features_ready`, coverage < 90% |
| **Шаги** | 1. Открыть панель coverage → 2. Список missing → 3. Подсказка: какое поле ввести вручную → 4. Повторить extraction или manual fill |
| **Результат** | Coverage ≥ 90% или осознанное продолжение с warning |
| **Альтернативы** | Missing только в na_trends — не блокировать (когортные константы) |
| **Фичи** | F-007, F-006 |
